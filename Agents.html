PATTERN 01 — THE KNOWLEDGE ENGINE

“We bought Copilot. It still can't find the contract.”

It's the most common AI complaint we hear from enterprises that have already invested in data. Users fall back to manual searching, productivity drops, confidence drops faster — and nobody has confirmed the actual root cause. There are four, and they are not all the tool's fault.

USER INTENT

A question a human could answer in ten minutes with the right file in front of them.

AI ASSISTANT

Copilot, an enterprise search tool, or a chat assistant wired to the tenant.

THE BREAK

Indexing, permissions, document quality or versioning — unconfirmed.

OUTPUT

Missing or incomplete — and a user who goes back to searching by hand.

Four root causes. Each one has a validation test.

We don't recommend a rebuild until we know which of these is actually biting. Two of them are configuration. Two of them are data work.

CAUSE 01 · ACCESS & INFRASTRUCTURE

Incomplete document indexing & access

Missing indexes, restricted permissions, repositories never connected in the first place.

We do: audit indexing, verify SharePoint and OneDrive permissions, review search scope, configure the missing connectors.

Validation test: can the affected user discover a file we know exists?

CAUSE 02 · DATA & CONTENT

Poor document quality & structure

Scanned PDFs, unreadable text, inconsistent formats, missing metadata. An agent cannot read what was never extracted.

We do: apply OCR, extract and normalise content, standardise metadata and document naming.

Validation test: measure extraction accuracy on the clauses that matter.

CAUSE 03 · SYSTEM & MECHANICS

Ineffective semantic retrieval

Irrelevant results, missed clauses, not enough context handed to the model to answer with.

We do: improve query specificity, add metadata filtering, evaluate hybrid search, and only then consider custom RAG with clause-aware chunking and reranking.

Validation test: measure correct document and clause retrieval rate.

CAUSE 04 · GOVERNANCE

Document versioning & governance

Duplicate contracts, outdated versions, missing amendments, unclear document status. The agent answers from v1 while the business runs on vFINAL_edited.

We do: centralise the document inventory, implement version tracking, link amendments, standardise lifecycle metadata.

Validation test: does it retrieve the latest effective agreement?

THE DIAGNOSTIC ROADMAP

Diagnose first. Optimise what you own. Build custom only when the evidence says so.

PHASE 1

Assessment

  • Select 20–30 benchmark questions from the real business.
  • Test indexing, document quality, retrieval and version relevance.
  • Identify the confirmed root causes — not the suspected ones.

PHASE 2

Improvement

  • Prioritise targeted fixes against those causes.
  • Re-test using the same benchmark questions.
  • Measure retrieval accuracy, answer quality and citation accuracy.

Key message: diagnose first, optimise the platform you already pay for where possible, and consider custom RAG only when necessary.

THE BLUEPRINT

The pipeline, the metadata and the retrieval — in that order.

This is the architecture when the diagnosis says build. Every layer sits inside an enterprise security and role-based access control boundary, so retrieval respects permissions rather than having them bolted on afterwards.

LAYER 01

Document sources

SharePoint, PDFs, Word, ticketing systems, wikis, shared drives — connected, not copied.

LAYER 02 — THE PIPELINE

Processing engine

OCR · extraction · clause-aware chunking · metadata generation. The step most teams skip, and the one that decides everything downstream.

LAYER 03 — INSIDE THE SECURITY & RBAC BOUNDARY

Hybrid search system

Keyword match + vector search + reranking. Hybrid because neither one alone finds a clause that is worded differently to the question.

LAYER 04 — INSIDE THE SECURITY & RBAC BOUNDARY

LLM generation

Synthesised answers with deterministic source citations — file and clause, every time, or no answer at all.

LAYER 05

Enterprise search portal or agent

Where the business actually asks the question — in a portal, in Teams, or through an agent with a bounded tool list.
